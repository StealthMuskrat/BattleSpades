# Environmental achievement rules

This checkpoint ports the remaining blast, terrain, crate, demolition and authored-region rule families from the unchanged original achievement engine into the standard Java host. It preserves the original rule evidence and existing external observation ports.

Blast scopes nest and close through `finally`, including corpse blasts inside a larger explosion and aborted scope bodies. A triple explosion counts only the thrower's accepted enemy kills with that scope's kill type. Buried-mine state is sampled from the solid cell at the blast origin before terrain changes. Dynamite records whether the charge was at least half a block below the victim's standing or crouching feet when damage occurred; that evidence can credit a subsequent fall. Direct rocket contacts require a live airborne thrower, a valid enemy and the configured bot-victim policy.

Turret rockets retain the launching entity object so an entity removal or numeric slot reuse cannot transfer its accuracy count. Ten kills belong to one turret. Evasion counts the terrain broken by rockets aimed at a player who remains alive and was not damaged by that blast. Pending projectile context is consumed by the next blast, matching the source type check. A drill bore has a scoped block cause without becoming a player-damaging blast.

Committed terrain removals and collapsed chunks drive zombie block counters, the source grenade structure threshold of 100 blocks, the minigun threshold of 50, demolition lifetime damage, 100 objective blocks in one match, drill objective damage and final winning damage. Bots can be the final objective damager, but earn no unlock. The existing demolition repair owner supplies repair counts after its own team, phase and self-damage checks.

Crate baselines are captured before the actual refill. Health uses positive restored health, reaching 150 in a match. Ammo uses positive reserve gains for the same weapon and that weapon's source reserve capacity. Full crates contribute zero; weapon totals are separate; sub-rounds retain match totals and full match restarts clear them. Existing crate award/profile/audio callbacks still receive their original baseline object.

Only map metadata already identified as stock is eligible for authored achievement regions. Kill regions use inclusive position bounds, optional team restrictions, per-round kill thresholds and the source Mayan-melee/Zombie-victim conditions. Destroy regions freeze their solid cells at match start, include collapse removals, and intersect contributors across every volume for the same achievement. An already empty volume at restart disables that structure's award for the new match. Periodic resynchronization checks remaining sets of at most 512 cells, allowing non-combat removals to finish a structure without inventing a contributor. Disconnected player objects cannot transfer contribution credit to a replacement slot. Source zombie, rocket and demolition restrictions are preserved.

No new retail volumes are guessed or added. The original repository implements 71 achievements and lacks usable recovered metadata for six more; Java retains the same data limitation. The 77-row catalog alone does not make those missing volumes available. This completes the environmental rule families, not ordinary standalone hosting or the broader migration.

Differential evidence adds 28 intact original-engine traces with 227 owner boundaries. Each boundary compares all human lifetime counters and earned/pending unlocks, covering nested and separate explosions, turret identity, below-feet thresholds, bot exclusion, structure sizes, crate scopes, demolition, shared/missing region contribution, resets, disconnects, authored kill conditions and resynchronization. A separate production-owner case exercises an actual triple-kill blast with nested corpse blasts and real map-crate refill callbacks. Existing source directories and resource fixtures remain unchanged; a new development-only exporter reproduces the new fixture in native CI. Production remains portable Java with worker-only achievement persistence.

Await achievement and result shutdown in their existing order. The achievement file's 8 MiB limit and the separate achievement/outbox transaction boundary remain unchanged. No supported-client acceptance or full migration completion is claimed. macOS testing remains deferred until full migration completion.
