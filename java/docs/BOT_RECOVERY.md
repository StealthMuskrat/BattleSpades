# Bot recovery planning and execution

The Java recovery layer ports `server/bot_ai/recovery_skills.py` and `server/bot_ai/skill_driver.py` from source commit `546c548780c400f21d73ca6713f86194ceb3c844`. It provides weighted, resumable terrain searches, budgeted pillar/stair/bridge plans, live terrain revalidation, ordinary movement and tool proposals, and per-life recovery scheduling.

`RecoveryPlanning` retains tool footprints, protected floors, conservative swing estimates, block refunds, source search ordering, slice deadlines and expansion/radius limits. Search occupancy belongs to one search; live block health remains available to cost estimation. `RecoverySkill` handles alignment, visibility and reach, accepted/rejected build feedback, cadence, jump timing, momentum braking and blocked-step failures. `RecoveryDriver` retains request identity, water episodes, pending searches, progress watchdogs, bounded retries, avoided cells, bounded player slots and diagnostic events. Mutable objects enforce worker ownership.

The generated source fixture uses real compact VXL maps and canonical terrain edits. It records 21 geometry/profile queries, 24 retained searches, 177 executor boundaries and 451 driver boundaries, including failure and lifecycle paths. Search clocks are controlled inputs. Accepted terrain edits and player snapshots are explicit fixture inputs; these observations do not establish a connected Java physics loop or production bot play.

Live bots remain disabled. Production brain orchestration, mode/cooperative policies, director, gateway, motor and host composition remain unfinished. Full migration completion and final macOS acceptance remain outstanding. Existing standalone UDP map-reload intermittency is not claimed fixed by this work.
