# Standard hosted voting

This checkpoint completes the standard-host composition of the existing ranked rotation, retail map-ballot and vote-kick policies.

| Implementation | Hosted behavior |
| --- | --- |
| Startup configuration and ranked rotation | Parse and normalize lobby rotation, one-time shuffle, size overrides, fit/recency/retail-cap policy and kick thresholds. Discover maps, retail pools and navigation areas once on the startup worker. Ranking during gameplay reads an immutable catalog. |
| Map ballots | Countdown and explicit mode requests open ranked candidates. Retail packet 47 votes use the actual connection's player, reveal the current overlay to late joins, resolve/consume the selected map, and retain catalog/history through scene rollover. |
| Vote kicks | Retail packet 48 starts or cancels a kick; packet 47 records votes. Verified room-creator principals are protected. A successful majority disconnects the target and excludes its address until the match resets, while address cooldowns survive restarts and slot reuse. |

Create `VotingSettings.from(rawToml, gameRules)`, await `settings.prepareCatalog(mapRoot, workerRandom)` on the startup worker, construct the prepared `HostedSceneState`/`ApplicationHost`, and call `HostedVoting.standard(host, state, catalog, settings, clock, loop)` before initial scene attachment and before connections. It rejects an already attached standard domain. Existing custom-domain constructors still require their own gameplay routing; every voting owner now binds to its host before connections.

The host owns one voting service. Standard domains automatically use it for map/kick packets, catch-up overlays, countdown requests, round-ending vote priority and match-start resets. Transitions cancel old ballots and note the played map. The source-ordered second scheduler ticks ballots once per 60 simulation ticks independently of whether the mode clock has ended. The supplied clock owns ballot deadlines and address cooldowns; owner-loop timers retain the existing independent map-result waiter behavior.

A scene's media owner no longer closes the shared ballot on retirement. The replacement domain retains the same immutable catalog, rotation history and address cooldowns. Match start and admin restart/rollover clear ballots, consumed selections and match exclusions. Room-creator protection reads the existing verified `HostedAdministration` principal; ordinary administrator status alone does not grant room-host protection. No packet-provided player ID establishes the voter.

Admission checks compose in order: persistent administration bans, the embedding's admission gate, then match vote-kick exclusions. Voting does not replace an existing gate and does not write a vote kick to the persistent ban file. The host closes voting before releasing connections; ballot waiters/timers are retired and scene disposal does not dispose another scene's voting state.

The lobby parser clamps the source numeric ranges and rejects non-finite values, malformed types, invalid size classes and path-bearing rotation entries. Rotation names are normalized and deduplicated by Unicode casefold. Path components are rejected rather than silently stripped. Size classes and explicit areas use the same source ranking policy. There is no disk scan or navigation decode in ballot ranking.
