# HUD presentation and achievement foundations

This checkpoint completes the remaining standard-host HUD helpers and adds the achievement catalog, portable transactional persistence, legacy database export, and hosted generic combat/lifetime tracking. Ordinary application hosting and the full achievement rule set remain incomplete.

The handwritten packet-41 codec uses the original signed ID, key, BGR tint, fixed coordinates, icon string and tracking flag. HUD markers accept only the 68 original stock icon names and finite clamped coordinates. Tracking markers require a known entity; loader replay accounts for preceding CreateEntity packets and keeps the marker after its entity. Global and private markers support updates, partial clears and replay. Explicit audiences retain connection capabilities rather than reusable player IDs. Private audiences are retired on disconnect. Same-scene restart clears all minimap markers before entity IDs can be reused; new scenes discard old presentation state. Camera focus uses the same recipient and coordinate guards. The original disabled ProgressBar policy is retained: no packet 65 is emitted.

All 77 retail achievement definitions and their tier thresholds are exported from the unchanged original table. The Java store uses a separate, versioned JSON file. Every transaction takes a process lock, reads the current state, merges counter increments, arbitrates unlocks, optionally marks master handoffs, and atomically replaces the file after flushing its bytes. The portable file currently uses the common 8 MiB document limit; large fleet capacity remains unverified. Multiple Java server instances can share this file; cached snapshots never overwrite another instance's increments. A busy or failed store retains host deltas for retry. Announcements occur only after a durable unlock acknowledgment. Disk operations run on a dedicated worker. Prepare the service before admitting players and await host achievement shutdown before closing the host.

Existing SQLite databases are not opened for writing by Java. During cutover, stop legacy writers, then run:

```sh
python java/tools/export_legacy_achievements.py --source achievements.sqlite --output achievements-java.json
```

The offline exporter reads one SQLite snapshot in read-only mode, preserves counters, names, unlock times and reported times, and refuses to overwrite an output file. Supply the exported path to `HostedAchievements.prepare(path)` and bind the prepared service with an independently verified identity resolver. A null path explicitly selects volatile memory. Verified AoSPlay identity takes priority over verified Steam identity, with the original pinned-Unicode name fallback for direct legacy clients. Bots have no achievement identity. Human counters, identity and fractional measurements survive scene replacement without retaining retired worlds.

The standard hosted hooks now cover accepted generic kills and misses, weapon-specific counters, kill streaks, sniper accuracy and rapid kills, active jetpack kills, victim jetpack state captured before death clears flight, low-health kills, credited rocket falls, classic carried-intel kills, running distance and airborne time. Bot-kill policy, playable teams, transition deaths and ended rounds retain their original gates. Movement is measured at the achievement frame phase; teleports over two blocks are excluded. Counter flushes, disconnects, match changes and shutdown use the same durable owner.

The asynchronous `takeUnreported` API performs a durable one-time handoff. Its integration with the existing synchronous round-result callback remains future work. Explosion/region/crate and mode-specific objective/round achievement families also remain to migrate; definitions do not imply those rules are implemented. No unsupported Steam write or real-client acceptance is claimed.

The added source generator reproduces 134 intact-engine tier observations, eight generic combat traces, an original SQLite export, and native packet-41 vectors for all 68 icons. Existing source modules and frozen resources remain unchanged. Verification results and the four-job CI evidence are recorded after consolidated validation. macOS remains deferred until full migration completion.
