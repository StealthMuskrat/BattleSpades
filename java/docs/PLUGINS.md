# Portable Java plugin layer

This batch implements trusted local plugin discovery, the lifecycle/event manager, host callback composition and an opt-in Java port of the source example. The Java SPI replaces Python imports for the portable target; it does not execute Python plugins. Ordinary competitive startup remains gated while bots, remaining composition and supported-client acceptance are unfinished.

`RuntimePlugin` provides load/unload/enable/disable hooks and a generic `ModeEvents.Event` callback. The host context exposes the owner executor, host, current-match lookup, top-screen announcements and queued informational logging when a host logger is bound. Metadata names stay stable. Plugin constructors and callback prefixes run on the authoritative owner; worker completions resume through `OwnerSequence`. Plugins must submit authoritative continuations through the context's owner executor after their own background I/O.

`PluginManager` preserves source registration order, duplicate-name rejection, ordinary load failure isolation, enabled gates and serial callbacks within each event. Enable/disable changes state before its lifecycle hook. An ordinary unload failure is reported and the entry is removed. Ordinary event faults leave later callbacks eligible. Cancellation and fatal callback errors propagate. In-flight names are reserved so overlapping asynchronous loads cannot overwrite one another. Dispatch snapshots membership and checks current entry identity before each callback, avoiding mutation-during-iteration failures. These two concurrency safeguards make the Java lifetime explicit.

Tick callbacks share the configured elapsed-time budget (default 2 ms, minimum 0.1 ms). The source budget check happens before each enabled callback and includes elapsed time spent awaiting earlier callbacks; it cannot preempt a running plugin. Every skipped enabled callback increments `skipped_plugin_callbacks`; warnings are throttled to one per monotonic second. Other mode events have no tick budget. Generic callback return values do not veto gameplay, matching the source manager.

`PluginCatalog.prepare` runs on a worker. It scans sorted public top-level `.jar` files, ignores private and disabled names, resolves candidates beneath the configured real root, validates the archive and discovers implementations through Java ServiceLoader. Providers are sorted by class name. Broken archives, provider descriptors and optional linkage failures are isolated per artifact. Provider factories instantiate later on the owner, before matching instance metadata names; an explicit denied JAR stem is skipped before class loading. Casefolded allow/deny filters match JAR stems or plugin names, with deny taking priority. The configured enable switch skips discovery. Missing directories are empty. Each JAR has its own parent-first classloader; application/API classes keep their host identity. This is trusted local extension loading with ordinary process privileges, not a sandbox.

The catalog retains its classloaders until accepted lifecycle/events finish and unload hooks run. Classloader disposal returns to the retained worker. Await `HostedPlugins.ready()` before starting hosted simulation, then await normal simulation shutdown before releasing that worker. The host rejects close until plugin shutdown has completed. A plugin instance survives scene rollover and resolves the current match when needed. Its own saved references remain its responsibility.

Hosted standard mode-event delivery invokes the plugin manager and preserves existing external observers. The PLUGINS frame phase supplies `on_tick` with the real loop integer and preserves the external frame service. Shutdown retains suspended events, unloads in registration order and finishes before telemetry shuts down, allowing final plugin logs to drain. Existing authoritative command/admission/chat/build policies remain in their established owners; the source's unused boolean/string hook declarations do not introduce new veto semantics.

The separate `java/examples/plugins/ExamplePlugin.java` ports the original private example's 3/5/10 kill-streak overlay announcements. It remains opt-in and is absent from the application artifact's provider registry. Its source intentionally tracks numeric player IDs, matching the original example rather than acting as the achievement authority. [Packaging instructions](../examples/plugins/README.md) describe the ServiceLoader descriptor and owner API.

The new source exporter runs the unchanged Python manager and example. It records lifecycle, enabled/budget boundaries and every example kill's resulting announcements. Tests build actual plugin JARs with the installed Java 25 compiler, load the separate example through ServiceLoader and check original-policy observations. Worker completion tests verify owner resumption and retained shutdown. A real ENet host test suspends an external plugin while another client loads and clock packets continue, then reloads the map with the same plugin instance and verifies suspended shutdown before deleting its JAR.

The original source directories and existing resource fixtures remain unchanged. macOS testing stays deferred until the full migration is complete.
