# Same-map restart, teleport and live reconciliation

The hosted standard match now implements three further administrator command families, extending [SERVER_CONTROLS.md](SERVER_CONTROLS.md).

| Command | Aliases | Behavior |
| --- | --- | --- |
| `/restart` | `reset` | Retire the old round, await bot preparation, release the forced score overlay, reset transient runtime state, restart the active mode/objectives, publish zero scores, respawn current connected playable lives, await the bot round reset, then announce completion. |
| `/tp <player> [destination]` or `/tp <x> <y> <z>` | `teleport` | Move self to another player, move a named player to another player, or move self to finite coordinates inside the native 512×512×240 map bounds. Coordinate teleports zero velocity; named teleports retain it. |
| `/netcode [selfrow on\|off] [offset <n>] [interval <n>]` | `nc` | Query or atomically tune the actual replication owner's self-row inclusion, loop offset and cadence. `self` also names `selfrow`; on/true/1 enable it. Interval is at least one. |

Commands use the existing canonical queue and administrator policy. Restart uses `MatchTransitions.restart()` and the existing `RoundRestart` sequencer. `HostedTransitionServices` binds standard domains to actual score, mode, player, entity and construction owners; custom domains retain their explicit restart binding. Its service bindings now also require `resetBotsAfterRestart()`, separately from a map/mode bot rebind. Bot preparation, bot reset and HUD clearing remain required embedding services; the migration still has no production bot director.

The standard mode's start path resets match/life counters, result baselines, construction reservations, prefabs, corpse state, entities, deployables, projectiles and surface effects, then rebuilds resources/objectives. The restart owner also resets kill-feed relationships and awaits leaves arriving during bot preparation before discarding the old queued timeline and starting the new mode. The same world, terrain edits, mode, connected player objects, administrator principals, fog override and network connections survive. Ordinary spawn applies pending selections, restocks and publishes CreatePlayer. Spectator cameras are retained. Player snapshots are taken after asynchronous service preparation, so departed player IDs do not receive replacement lives. The connected check includes admitted connections still loading; a failed spawn is isolated and reported through the match failure owner. Production round-ending and other external services remain mandatory.

Teleport updates the actual mover, clears stale water contact and the old fall's parachute-used latch, and retains held/deploy intent, flight fuel, the life generation, input labels and existing causal owner anchors. It replaces the position-report baseline so an already accepted client-authority report cannot immediately undo an administrative move. This is an intentional consistency improvement over the original setter. Current telemetry counters and timestamps are retained. Position bounds are also enforced for a named destination; invalid destinations fail through command error handling. Subsequent normal snapshots publish the new position without inventing input acknowledgements or a new life.

Live reconciliation uses an owner-confined `ReplicationService.OwnerTuning` value. Tuning leaves broadcast buckets, prior owner anchors, observer state, reliable holds and input timelines intact. The host retains the last successful override and applies it to replacement player runtimes after map/mode reload. A fresh process reads normal configuration. Malformed multi-key commands leave all knobs unchanged, improving on the source command's incremental mutation. Offsets and interval arguments use signed 32-bit values; resulting owner feedback labels clamp into the signed nonnegative wire range rather than overflowing a simulation frame.

The existing source command and restart semantics guide this batch. Dedicated component cases exercise live cadence/history and label bounds, plus water/parachute/velocity/life preservation. Two actual UDP cases exercise suspended restart preparation/reset with continuing loading/clock packets and slot reuse, scene/terrain/fog/score/spectator preservation, authorization and teleport commands, atomic tuning and tuning persistence through same-map restart and real map reload. Existing mode-start, round-restart and replication golden suites remain in the consolidated checks.

The wider migration remains incomplete: bots and Tutorial, achievement evaluation/local profile persistence, master registration/authentication, remaining fun/plugin commands and ordinary standalone match startup still require work. Supported retail-client acceptance is not claimed.
