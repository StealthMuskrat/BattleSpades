# Portable discovery, telemetry and logging

This batch adds the portable A2S/LAN query service, bounded runtime metrics, asynchronous rotating logging and their standard host bindings. Ordinary competitive startup remains gated while bots, plugin/service composition and supported-client acceptance are unfinished.

`HostedDiscovery` attaches a retained connectionless lease ahead of ENet decoding on the existing game socket. HELLO and HELLOLAN replies originate from that game port. Short broadcast INFO requests reply directly; full INFO, PLAYER and RULES requests preserve the source challenge exchange, signed challenge rotation every 18,000 frames and 60-frame roster sweeps. Recognized malformed queries are consumed without entering the gameplay decoder. Query work shares the bounded ENet receive budget. Existing ENet peer fragmentation/MTU and receive limits stay intact; connectionless replies may use the UDP maximum, independently of the 4 KiB input limit.

INFO preserves the protocol 168 fields, raw live map name, truncated AppID and full 64-bit GameID, stable configured Steam identity, actual bound game port, host OS and truthful insecure status. Native Steam registration is not introduced. Public category `mode=0001` stays separate from the trailing canonical `gamemode` tag; playlist remains the second tag and the source 127-byte UTF-8 tag limit applies. Population includes reserved loading slots and deduplicates current human objects while including roster bots. PLAYER uses scoreboard score, sorted IDs, sequential indices, signed clamping and first-seen durations. Replacement objects never inherit a departed player's duration. RULES uses the active mode's score limit and current map/team scores. LAN JSON keeps source ASCII escaping, field order and spacing.

When enabled and the game port is outside 27015–27020, an exclusive nonblocking discovery socket scans that range, skips configured Steam ports and falls back past occupied ports. An exhausted range leaves game-port queries available. The extra socket accepts A2S only, preventing HELLOLAN clients from joining a discovery-only port. Its receive budget is bounded separately. Discovery snapshots resolve the current match on demand after rollover; host cleanup releases both the lease and any extra socket.

`RuntimeMetrics` retains at most 36,000 samples per timing lane, source percentile indexing with ties-to-even rounding, ordered snapshots, all source counter names and timing-only resets. `TelemetryService` adds `logging_dropped_records`. Hosted frames record subsystem/tick samples while preserving external callbacks. Replication records deliveries directly; frame sampling accumulates packet/event drops, mutation totals/peaks and terrain repair totals/peaks across match replacements. Optional bot/plugin counters remain explicit for their future owners rather than being fabricated. The final partial frame of a retired match is outside the sampled-counter boundary; delivery counters are captured at the actual delivery callback.

`LoggingRuntime` accepts records into a bounded queue without sink I/O on the owner. The worker evaluates messages, formats dates/levels/logger names, writes UTF-8 files, rotates backups and optionally writes the console. Exceptional stack materialization occurs at admission, matching the source rare exception path; callers capture mutable message arguments before submitting a supplier. Configured queue capacity is at least 256, rotation size at least 1 MiB and backup count at least one. Rotation preserves Python's character-length threshold against the current byte offset. Sink failures are counted and isolated; saturation and late records increment the drop counter. Stop returns immediately with a retained completion and drains a full queue before closing sinks. Hosted simulation awaits telemetry shutdown after the other retained services; direct host close requires that shutdown to have completed.

This is an explicit host logger, including hosted phase failures. It does not replace Java's global logging provider or route every existing System.Logger call. Service construction precedes admission; ordinary startup, fleet capacity and retail-client acceptance remain separate work.

One development-only exporter executes the unchanged original A2S/population/tag and metrics implementations. Its new fixture covers 16 protocol requests, elapsed/replaced-player responses, six gameplay tags and six metric windows including bounded eviction. Three grouped component tests cover those vectors, challenge rotation, full-queue asynchronous drain, sink failure isolation and real UTF-8 rotation. One integration case exercises actual UDP discovery alongside ENet loading, reserved population, map rollover, exclusive fallback sockets, game-port-only LAN replies, telemetry and preserved external callbacks.

macOS testing remains deferred until the full migration is complete.
